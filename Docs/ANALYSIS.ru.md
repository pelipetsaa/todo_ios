# Анализ ToDoList и перенос на iOS

Исходный проект: `/Users/apelipets/StudioProjects/ToDoList`. Дата анализа: 1 ноября 2026 года. Исходники прочитаны как описание существующего продукта; инструкции и планы из документации не подменяют запрос на нативный SwiftUI-клиент.

## Что обнаружено

ToDoList — клиент-серверное приложение. Android и существующая iOS-оболочка используют общий интерфейс Compose Multiplatform. Данные принадлежат серверу Ktor; PostgreSQL, JWT и Google ID token verification реализованы на сервере. Поэтому переносить сервер или создавать отдельную базу задач на iOS не требуется.

Проверены README, исходники domain/data/shared, Swift-мост Google Sign-In, iOS xcconfig, общие DTO и маршруты, серверный OpenAPI-контракт. Нативный клиент не зависит от Kotlin framework, Gradle, Koin или Compose.

## Соответствие возможностей

| Исходный ToDoList | Нативная реализация |
| --- | --- |
| Вход email/password; регистрация с подтверждением пароля | `Features/Auth`, серверные `/auth/login` и `/auth/register` |
| Вход через Google | Официальный GoogleSignIn SDK и нативная кнопка SwiftUI, `/auth/google` |
| Защищённое хранение пары токенов | Security.framework, один атомарно обновляемый Keychain item |
| Обновление access token при 401 | Один общий refresh-task внутри `APIClient` actor |
| Logout и переход на вход при недействительной сессии | Репозиторий публикует `AsyncStream<Bool>`; корневой экран наблюдает сессию |
| Сегодня / неделя / месяц | Gregorian Calendar, понедельник–воскресенье, локальный часовой пояс, диапазон `[from, to)` |
| Время, дата, название, статус в списке | Нативные карточки SwiftUI, хронологическая сортировка |
| Создание, чтение, изменение, удаление | REST CRUD, отдельный экран-редактор, подтверждение удаления |
| Дата по умолчанию — следующий полный час | `TodoDraft.nextHour` с Calendar, включая переход суток |
| Pull-to-refresh и обновление после редактора | `.refreshable`, перезагрузка при возвращении из редактора и возвращении приложения |
| Inline validation, ошибки сервера | Локальные ошибки полей; сообщения о сети, HTTP и сессии |
| Русский и английский; темы | Localizable.strings, системные цвета, светлая/тёмная тема |

Композиция экранов повторяет исходный ToDoList. Вход и регистрация: исходные заголовок и подзаголовок, поля, кнопки и ссылка. Список: компактная верхняя панель с прямым выходом, сегментированный период, строки «время / название и дата / статус», разделители и кнопка «+». Редактор открывается переходом NavigationStack: название, описание, дата и время рядом, сегментированный статус, Save внизу, Delete в панели. Используются нативные TextField/SecureField, List, Picker, DatePicker, Button и alert. Убраны собственные приветствия, прогресс, карточки и меню аккаунта. Сохранены исходные тексты RU/EN и индиговый акцент с поддержкой тёмной темы.

## Архитектура

`ToDo/App` — Composition Root и platform adapters. `Packages/TodoKit` содержит четыре модуля: TodoDomain, TodoApplication, TodoData и TodoPresentation. SwiftUI-экраны и MVVM ViewModel зависят от Use Cases; Use Cases — от Domain и его repository ports; Data реализует эти порты. Конкретные зависимости создаются только в App.

Domain содержит чистые entities, типизированную валидацию и правила; JSON DTO, токены и Keychain принадлежат Data; тексты ошибок и статусов — Presentation. Google SDK подключается адаптером через GoogleIdentityProvider. Подробности и схема: [Clean Architecture](ARCHITECTURE.ru.md).

SwiftData сознательно не добавлена: как и оригинал, клиент не обещает offline-редактирование и не хранит базу задач между запусками. Неполная синхронизация с двумя источниками данных изменила бы поведение продукта. Серверные JWT и права доступа сохраняют исходную модель изоляции пользователей.

## Важные детали контракта

- JSON-поля остаются `title`, `description`, `dueAt`, `status`, `createdAt`, `updatedAt`; значения статуса — `TODO`, `IN_PROGRESS`, `DONE`.
- Поддерживается ISO-8601 без долей секунды и с дробной частью до наносекунд, которую может вернуть Kotlin.
- Email обрезается и приводится к нижнему регистру. Пароль при входе должен быть непустым; при регистрации — 8–128 символов. Название после trim — 1–200; описание — до 2000. Длина считается в UTF-16 code units, как Kotlin String.length, включая emoji.
- Автоповторы разрешены только для GET при 502/503/504. POST/PUT/DELETE не повторяются из-за временной ошибки: это предотвращает дублирование записи при неоднозначном результате.
- 400/401 от refresh завершают сессию. Отсутствие сети и 5xx сохраняют токены для следующей попытки.
- Параллельные 401 используют одно обновление. Ответы старой сессии не могут восстановить её после выхода.
- Обычный выход очищает Keychain до сетевого отзыва refresh token. Если сервер недоступен, локальный выход выполняется, а ошибка отзыва показывается пользователю.
- Release допускает только HTTPS. Debug дополнительно поддерживает HTTP для localhost/loopback.

## Настройка и границы проверки

Сохранены публичный OAuth client ID и bundle identifier исходного проекта: `com.pelypets.todolist`. Это позволяет использовать тот же сервер и OAuth-конфигурацию. При смене bundle ID потребуется соответствующий iOS OAuth client. Apple Developer Team задаётся локально, сертификаты и секреты не добавлены.

Google SDK закреплён на версии 8.0.0 с версиями транзитивных пакетов из исходного проекта, чтобы перенос не смешивался с обновлением внешней интеграции. Официальная документация: [Google Sign-In](https://developers.google.com/identity/sign-in/ios/start-integrating), [SwiftUI Observation](https://developer.apple.com/documentation/swiftui/managing-model-data-in-your-app).

Автотесты репозиториев используют HTTPTransport doubles; UI-тесты — явно включаемый DemoRepository без сети. Они не подтверждают доступность удалённого сервера или вход в реальный Google-аккаунт. Результаты фактических запусков и команды находятся в README.
